Real Results

Before & After Cerverus

Here's what the AI agents actually do to your code. The Red Team finds the vulnerability, and the Blue Team writes the fix.

❌ BEFORE — Vulnerable Code 
# VULNERABILITY: SQL Injection
# User input directly in SQL query

@app.route("/search")
def search_users():
    name = request.args.get("name", "")

    # ⚠️ DANGEROUS: raw string interpolation
    query = f"SELECT * FROM users
             WHERE username = '{name}'"

    results = db.execute(query).fetchall()
    return jsonify({"results": results})
✅ AFTER — Patched by Blue Team 
# FIXED: Parameterized query
# User input safely bound as parameter

@app.route("/search")
def search_users():
    name = request.args.get("name", "")

    # ✅ SAFE: parameterized query
    query = "SELECT * FROM users
             WHERE username = ?"

    results = db.execute(query, (name,)).fetchall()
    return jsonify({"results": results})
VULN-002 Critical
SQL Injection — User input was interpolated directly into SQL query strings without parameterization. An attacker could inject ' OR 1=1 -- to dump the entire database, modify records, or escalate privileges.
🧠 Ontology Rule Added: "Always use parameterized queries with placeholders for all dynamic values."
